# C10 Team Kagera — Toxicity Linear Probe (Gemma-2-2B Layer 14)

A lightweight toxic-comment classifier built by training a **linear probe**
(StandardScaler + Logistic Regression) on frozen hidden-state embeddings
extracted from **Gemma-2-2B**, rather than fine-tuning the full language
model. The probe is trained on the Civil Comments dataset and deployed as
an interactive Streamlit app.

## Dataset

We use **[Civil Comments](https://huggingface.co/datasets/google/civil_comments)**,
loaded via `datasets.load_dataset("google/civil_comments")`. It contains
~2M public comments from the now-defunct Civil Comments platform, each
annotated by multiple crowd raters with a continuous `toxicity` score in
`[0, 1]` (fraction of raters who flagged the comment as toxic), plus
sub-attribute scores (insult, threat, identity attack, etc., unused here).
Full provenance, schema, license, and known limitations are documented in
`docs/data_card.pdf`.

We selected this dataset because it is (a) large, public, and permissively
licensed, (b) pre-scored by human raters rather than a model (avoiding
label leakage from another classifier), and (c) a standard benchmark for
toxicity/bias research (it underlies the Jigsaw Unintended Bias Kaggle
competition).

**Label construction:** the continuous score is binarized with a threshold
of `toxicity >= 0.5` → `label = 1` (toxic), else `0` (safe).

**Subsampling:** to keep embedding extraction tractable on one GPU, we
shuffle (`seed=42`) and take the first **15,000** training / **5,000**
validation examples (set `TRAIN_SIZE`/`VAL_SIZE` to `None` in
`scripts/src/config.py` for the full corpus). The subset is
class-imbalanced (toxic comments are a minority), handled during training.

## Training Pipeline

1. **Data collection** — download Civil Comments via Hugging Face
   `datasets` (`scripts/pipeline/00_download_data.py`); no manual
   collection was required.
2. **Preprocessing** — shuffle, subsample, and binarize labels
   (`scripts/src/data.py`); tokenize with the Gemma tokenizer
   (`max_length=64`, truncation, dynamic padding).
3. **Feature extraction** — rather than fine-tuning, we run each comment
   through the **frozen** `google/gemma-2-2b` model in fp16 and take the
   hidden states at **layer 14** (of 26), then **mean-pool** over
   non-padding tokens into a fixed-size vector (`scripts/src/embeddings.py`).
   Layer 14 (mid-network) was chosen as a point where prior probing work
   suggests concepts are well-formed without being over-specialized to
   next-token prediction.
4. **Hyperparameter search** — a small grid over the classifier head:
   `C ∈ {0.001, 10.0}` and `class_weight ∈ {None, "balanced"}`, scored by
   validation accuracy (`scripts/src/train.py::hyperparameter_search`).
   Given the class imbalance, `class_weight="balanced"` is expected (and
   observed) to perform best.
5. **Final model** — the best configuration is refit on the full training
   embeddings and saved to `data/models/classifier.joblib`.

**Key design choices:** probing instead of fine-tuning keeps the 2B
backbone frozen/reusable and gives a fast, interpretable baseline for how
linearly separable toxicity is in Gemma's space; mean pooling avoids
relying on a single, padding-sensitive token; fp16 + `device_map="auto"`
keeps GPU memory low enough for a single consumer/Colab GPU.

## Evaluation

The final probe is evaluated on the held-out validation embeddings
(`scripts/src/evaluate.py`) using:
- **Accuracy** on the binarized labels.
- **Classification report** (precision/recall/F1 per class), which matters
  more than raw accuracy given class imbalance.
- **Confusion matrix**, to inspect false-positive/false-negative trade-offs.

Verification: saved embeddings are reloaded and shape-checked before
training; the exported `predict()` function is smoke-tested on validation
embeddings (correct shape, labels in `{0,1}`); hyperparameter search
results are logged to `data/models/hyperparameter_search.csv`. Risks,
mitigations, and success criteria are detailed in
`docs/impact_statement_card.pdf`.

## Reproduction

```bash
pip install -r requirements.txt

# 0. (Optional) verify dataset download
python scripts/pipeline/00_download_data.py

# 1. Extract Gemma layer-14 embeddings for train/val subsets
python scripts/pipeline/01_extract_embeddings.py

# 2. Hyperparameter search + train + save the final probe
python scripts/pipeline/02_train_probe.py

# 3. (Optional) re-evaluate a saved probe
python scripts/pipeline/03_evaluate.py

# 4. Launch the interactive app
streamlit run scripts/app/streamlit_app.py
```

Run in order 0→3: each stage consumes the prior stage's saved artifacts.
GPU recommended for steps 1 and 4; step 2 is CPU-only and fast.

### Code

All code required to reproduce results from scratch is under
`scripts/src/` (modules), `scripts/pipeline/` (ordered stages 0–3), and
`scripts/app/` (Streamlit deployment). No external, undocumented code is
required.

### Data

Civil Comments is not redistributed here due to its size; it is
downloaded and cached automatically via the Hugging Face `datasets`
library on first run of `scripts/pipeline/00_download_data.py` /
`01_extract_embeddings.py`. Generated embeddings and the trained probe
are regenerated by running the scripts above in order — see
`data/README.md`.
